## 2. 项目目标

在计划周期内完成可运行的 EmbodTeachMS 具身课堂 PoC，使评审能够通过教师和学习者双角色理解课程资料如何进入教学班、教师如何备课发布、学习者如何完成课程活动，以及系统如何形成学习证据和教师分析结果。

最终形成：

- 可运行产品 Demo。
- 完整项目源代码。
- 产品需求、技术架构、实施方案、项目计划和产品使用指南五份文档。
- 可复现的安装、启动、测试和演示流程。

## 3. 项目范围与优先级

### 3.1 P0：必须完成

1. 教师/学习者注册登录和权限隔离。
2. 教学班创建、发现、加入、申请审批和授权码。
3. 教师级知识库、Markdown 文档、分段、索引和班级导入。
4. 教学班备课、重点、题目确认和课程/作业发布。
5. 学习者课程、练习、作业和个人概览。
6. 教师班级统计和学习者结构化证据。
7. AI 能力明确降级和确定性事实隔离。
8. Three.js 具身智能三维教学演示。
9. 一键启动、自动化测试和最终交付文档。

### 3.2 P1：条件允许时优化

- 更丰富的图表和响应式布局。
- AI 评估集和提示词效果优化。
- PDF/DOCX 真实 MinerU 联调。
- Webots 真实任务环境、Controller 和结果评价联调。
- 更完整的演示数据和异常场景录屏。

### 3.3 暂不纳入

- 生产级部署、正式 SLA 和大规模并发。
- 多课程、管理员、教务系统和组织治理。
- 主观题、模型评分和正式成绩。
- 多供应商路由、模型训练和云仿真。

## 6. 详细进度安排

### 6.1 第一阶段：需求和原型（7 月 20 日—7 月 23 日）

- 梳理课程教学问题和用户角色。
- 明确教师与学习者核心闭环。
- 制作交互原型并确定工作台信息架构。
- 输出 PRD v0.3、技术架构 v0.3 和实施方案。

### 6.2 第二阶段：核心底座（7 月 24 日—7 月 28 日）

- 建立 Vue + TypeScript 前端和 FastAPI 后端。
- 实现统一响应 DTO、请求标识和 OpenAPI 类型。
- 完成注册、登录、角色权限、教学班和成员模型。
- 建立 SQLite 初始化与自动化测试基线。

### 6.3 第三阶段：资料到发布（7 月 29 日—8 月 3 日）

- 完成教师级知识库和文档管理。
- 完成分段、索引、召回测试和教学班副本。
- 完成备课会话、划重点、题目确认和发布快照。
- 更新 PRD v0.6 和技术架构 v0.6。

### 6.4 第四阶段：学习闭环与智能能力（8 月 4 日—8 月 8 日）

- 完成课程阅读、完成记录、课堂练习、基准练习和作业。
- 完成个人概览、班级统计和学习者依据。
- 接入聊天模型网关并处理未配置、超时和非法输出。
- 完成 Three.js 三维教学演示和 Webots 协议页面。

### 6.5 第五阶段：稳定化与提交（8 月 9 日—8 月 12 日）

- 清理测试数据并准备本地演示账号。
- 校验 TypeScript、构建、后端测试和核心 E2E。
- 完善 README 中的 Demo、源码和运行说明。
- 统一产品名称和文档表述。
- 输出并跟踪 2.1–2.5 五份最终文档。

### 7.2 软件与环境

- Windows 10/11。
- Node.js 24、npm 11。
- Python 3.13、uv。
- Chrome。
- 可选：DeepSeek API、MinerU、Webots。

### 7.3 数据与材料

- Markdown 课程资料作为默认演示输入。
- 本地 SQLite 演示数据库。
- 项目内置三维模型、场景和教学任务。
- 不使用包含真实隐私信息的学习者数据。

## 8. 质量计划

### 8.1 质量门槛

- TypeScript 类型检查无错误。
- 前端生产构建通过。
- 后端核心测试通过。
- 双角色核心流程可连续演示。
- 所有接口使用统一响应 DTO。
- 不存在已知跨教师、跨班或跨学习者越权。
- 外部能力失败不会修改确定性业务结果。

### 8.2 检查节奏

| 检查点 | 检查内容 |
| --- | --- |
| 每次代码变更 | 编译错误、重复功能、接口类型和更新日志 |
| 每个模块完成 | 正常、异常、权限和幂等场景 |
| 每个里程碑 | 端到端主流程和范围偏差 |
| 最终提交前 | 文档、密钥、依赖目录、日志、构建产物和 Git 跟踪状态 |

## 9. 风险计划

| 风险 | 概率 | 影响 | 预防与应对 |
| --- | --- | --- | --- |
| Solo 开发进度不足 | 中 | 高 | 先完成 P0，删除非核心可视化和 P1 优化 |
| AI 接口不可用或变化 | 中 | 中 | 使用稳定网关、环境配置和明确降级 |
| MinerU 契约不确定 | 高 | 中 | 默认使用 Markdown，不承诺未验证格式 |
| Webots 环境难以复现 | 高 | 中 | Three.js 演示独立交付，真实仿真列为可选集成 |
| 权限缺陷 | 低 | 极高 | 后端集中校验、404 隐藏和自动化权限测试 |
| 数据重复或冲突 | 中 | 高 | 事务、唯一约束和幂等键 |
| 文档与实现漂移 | 中 | 中 | 以源码、OpenAPI、配置和测试为事实来源 |

## 10. 沟通与变更管理

- 项目由单人负责，不设置复杂会议机制；以里程碑和更新日志作为主要沟通记录。
- 新需求先判断是否属于当前 P0；超出范围的能力进入后续计划，不在提交前追加。
- 连续两次补丁仍未解决的问题需重新审视模块或接缝设计。
- 不实施旧代码和旧数据格式兼容，变更直接体现在当前接口和文档中。
- 每次操作更新根目录 `UPDATE_LOG.md`，记录文件、原因、影响和校验结果。
