## 2. 实施目标

本项目以“能够稳定演示并由他人复现”为实施目标，在单机 Windows 环境中交付以下成果：

1. 教师端课程资料、教学班、备课发布和学情查看主流程。
2. 学习者端入班、课程学习、练习、作业和学习概览主流程。
3. 基于 Three.js 的具身智能三维教学演示。
4. 可选 AI、MinerU 和 Webots 集成的稳定接口及明确降级。
5. 可运行源码、自动化测试、启动脚本和完整交付文档。

## 3. 实施原则

- **最简交付**：采用 Vue 单页前端、FastAPI 单体后端和 SQLite，不增加 PoC 不需要的基础设施。
- **模块化实施**：按身份、知识库、备课发布、学习评价、外部集成和质量保障分阶段交付。
- **接口先行**：前后端以统一响应 DTO 和 OpenAPI 为接口；调用者与测试使用同一接口。
- **确定性优先**：权限、成员关系、客观判分、发布状态和学习证据由后端规则决定。
- **外部能力隔离**：AI、解析器和仿真作为适配器接入，失败不污染确定性事实。
- **编译优先**：每次前端变更先通过 TypeScript 检查，再处理运行层问题。
- **不做旧兼容**：当前数据结构和接口直接按最终 PoC 设计实现，不保留旧格式兼容层。

## 4. 实施范围

### 4.1 包含范围

- 双角色账号与认证。
- 教学班准入和成员管理。
- 教师级知识库、班级副本、文档版本、分段与检索测试。
- 备课会话、重点、候选题确认和课程/作业发布。
- 学习、练习、作业、掌握度和教师分析。
- AI 网关、Markdown 解析、可选 MinerU 和 Webots 协议。
- Three.js 三维演示。
- 后端测试、前端类型检查、构建和 E2E。
- Demo、源码和 2.1–2.5 项目文档。

### 4.2 排除范围

- 生产级高可用部署和大规模并发。
- 管理员后台、教务系统和多组织权限体系。
- 主观题和模型主观评分。
- 多模型自动路由和模型训练。
- Webots 自由场景、多机器人或 ROS 2。

## 5. 实施架构与工作分解

### 5.1 模块分解

| 实施模块 | 前端工作 | 后端工作 | 验收接口/结果 |
| --- | --- | --- | --- |
| 身份与工作区 | 登录注册、角色导航、会话失效处理 | 用户、密码、JWT、工作区 DTO | 双角色可登录且越权被拒绝 |
| 教学班准入 | 发现班级、申请、授权码和教师审批界面 | 班级、成员、请求、授权码和策略校验 | 正式成员才能访问课程 |
| 知识库 | 文档管理、分段预览、召回测试和导入 | 版本、解析、chunk、FTS5、向量和副本 | 文档可追溯，班级副本独立 |
| 备课与发布 | 文档选择、划重点、题目确认和发布 | 会话状态、来源校验、发布门槛和快照 | 已确认题目形成可见课程/作业 |
| 学习与评价 | 阅读、练习、作业、概览 | 幂等完成、确定性判分、掌握度和作业状态 | 学习结果可被本人和教师查看 |
| 教师分析 | 班级指标、列表、个人依据 | 聚合查询与权限过滤 | 不暴露原始聊天和跨班数据 |
| AI 与解析 | 降级状态、来源显示 | 网关、结构校验、超时、Markdown/MinerU 适配 | 外部失败不影响核心数据 |
| 三维与仿真 | Three.js 演示、Webots 工作区 | Webots 配对、运行和事件协议 | 本地三维演示可独立运行 |
| 质量与交付 | E2E、构建、运行文档 | pytest、OpenAPI、启动配置 | 他人可按指南复现 |

### 5.2 接缝实施

| 接缝 | 实施方式 | 失败处理 |
| --- | --- | --- |
| 前后端接口 | FastAPI + Pydantic + OpenAPI + openapi-fetch | 统一 ApiResponse 错误和 request ID |
| 数据库 | SQLite 事务、唯一约束和初始化逻辑 | 写入失败回滚，不形成半状态 |
| 聊天模型 | OpenAI 兼容 HTTP 适配器 | 超时/非法响应后明确降级 |
| 文档解析 | Markdown 本地解析 + 可选 MinerU HTTP | 保存失败状态、原因和重试入口 |
| 仿真 | Webots Connector REST/事件协议 | 非法状态迁移或重复冲突由后端拒绝 |

## 6. 分阶段实施步骤

### 阶段一：需求冻结与技术基线

**工作内容**

- 确认产品角色、核心流程、范围和不做事项。
- 固定 Vue、TypeScript、FastAPI、SQLite 和 Windows 本地运行基线。
- 定义统一响应 DTO、错误码和 OpenAPI 类型生成流程。
- 确定 AI、解析器、Embedding 和 Webots 的外部接缝。

**完成条件**

- PRD 和技术架构可评审。
- 核心领域术语没有同义冲突。
- 前后端最小工程能够安装、编译和启动。

### 阶段二：身份、教学班与权限

**工作内容**

- 实现教师/学习者注册登录和会话恢复。
- 实现教学班创建、发现、自由加入、申请和授权码。
- 所有资源路由接入当前用户与归属校验。

**完成条件**

- 教师和学习者各自能够完成登录。
- 申请中用户不能读取课程。
- 跨教师、跨班和跨学习者访问被拒绝。

### 阶段三：知识库与课程资料

**工作内容**

- 实现教师级知识库和 Markdown 文档管理。
- 保存受控原文件、规范化内容、文档版本和解析状态。
- 实现分段预览、规则应用、FTS5 和可选向量索引。
- 实现召回测试和教学班独立副本导入。

**完成条件**

- 上传、编辑、替换和删除形成正确状态。
- 文档变更后旧索引失效。
- 来源文档可导入多个教学班，副本互不影响。

### 阶段四：备课、题目与发布

**工作内容**

- 创建或恢复教学班备课会话。
- 选择已完成处理的班级文档并装载段落。
- 实现在线划重点、候选题生成、手工题和教师确认。
- 实现课程/课堂练习与作业发布快照。

**完成条件**

- 未处理候选题存在时不能发布。
- 发布内容绑定当前来源版本。
- 只有教学班所有者能够发布到该班。

### 阶段五：学习、评价与教师分析

**工作内容**

- 实现已发布课程读取和幂等完成。
- 实现课堂练习、基准练习和作业草稿/提交。
- 实现确定性客观判分和掌握度计算。
- 实现个人概览、班级聚合和学习者依据。

**完成条件**

- 重复提交不产生重复证据。
- 学习者只能读取自己的结果。
- 教师只能读取自有班级成员的结构化依据。

### 阶段六：AI、文档解析与具身能力

**工作内容**

- 接入 DeepSeek OpenAI 兼容聊天接口。
- 对小A候选题和小D问答执行结构、来源和权限校验。
- 保留 Markdown 默认解析，提供 MinerU 外部适配配置。
- 完成 Three.js 三维教学演示和 Webots 协议工作区。

**完成条件**

- 未配置 API Key 时显示明确降级。
- 模型非法输出不进入题目或确定性事实。
- Markdown 主流程无需外部解析服务即可使用。
- 三维教学演示在现代浏览器本地运行。

### 阶段七：测试、稳定化与交付

**工作内容**

- 执行 pytest、TypeScript 检查、生产构建和 E2E。
- 准备演示账号、教学班和推荐演示路径。
- 检查密钥、日志、依赖目录和构建产物不进入提交。
- 完成 README 和 2.1–2.5 五份文档。

**完成条件**

- 核心双角色流程能够连续演示。
- 已知未完成能力在文档中明确说明。
- 接收方可以按产品使用指南复现运行。

## 7. 数据实施方案

### 7.1 本地数据

- 默认使用 `backend/data/course-agent.db`。
- 应用启动时初始化需要的表和索引。
- 上传资料保存在 `backend/data/knowledge-base-uploads/` 等受控目录。
- 数据库、上传资料和 `.env` 不作为公共源码交付中的通用样例；提交前检查是否包含敏感数据。

### 7.2 版本与幂等

- 文档编辑、替换和分段重建更新版本或索引状态。
- 发布保存来源版本快照。
- 用户与教学班成员关系唯一。
- 课程完成、练习运行、作业提交和 Webots 事件使用唯一约束或幂等键。

### 7.3 数据迁移边界

PoC 不建立正式跨版本迁移体系。若结构变化，以明确的破坏性更新和测试数据重建为准；生产化时另行设计迁移、备份、回滚和归档方案。

## 8. 测试实施方案

| 层次 | 工具 | 重点 |
| --- | --- | --- |
| 后端领域与接口 | pytest / HTTP TestClient | DTO、权限、状态、事务、幂等和错误 |
| 前端类型 | vue-tsc | 严格类型、未使用项和接口一致性 |
| 前端构建 | Vite | 生产构建和资源打包 |
| 端到端 | Playwright | 双角色主流程和关键失败态 |
| 外部能力 | 固定替身 + 手工验收 | 超时、降级、非法结构和真实服务连通性 |

执行命令：

```powershell
cd backend
uv run pytest

cd ..\frontend
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:e2e
```

## 9. 部署与运行实施

### 9.1 开发和演示环境

- Windows 10/11 64 位。
- Node.js 24、npm 11。
- Python 3.13、uv 0.8 或更高。
- 现代 Chrome 浏览器。

### 9.2 启动方式

推荐在根目录运行：

```powershell
.\start.ps1
```

默认前端端口 `45173`、后端端口 `38117`。脚本生成本地 JWT 密钥、设置 CORS/API 地址、启动两个进程并在退出时清理本轮进程树。

### 9.3 配置管理

- 必需配置：JWT、数据库路径、CORS、前端 API 地址。
- 可选配置：AI Key/Base URL/模型名、MinerU 地址和解析限制。
- `.env` 和运行密钥不得提交；`.env.example` 保留配置字段示例。

## 10. 风险与应对

| 风险 | 影响 | 应对措施 | 止损条件 |
| --- | --- | --- | --- |
| 外部模型不可用 | AI 问答或候选题失败 | 超时、结构校验和明确降级 | 不影响确定性主流程，不继续增加模型补丁 |
| 文档解析失败 | PDF/DOCX 无法进入知识库 | Markdown 作为默认路径，失败状态可见可重试 | 正式 MinerU 契约未确认前不宣称完整格式支持 |
| 权限遗漏 | 数据越权 | 后端统一归属校验和权限测试 | 任一越权缺陷视为阻断项 |
| 状态重复 | 重复成员或学习证据 | 唯一约束、事务和幂等接口 | 不能以页面防重复替代后端约束 |
| Webots 环境不一致 | 真实仿真无法复现 | 协议隔离、环境检查、Three.js 独立演示 | 未实测前不承诺兼容性和性能 |
| Solo 开发时间不足 | 非核心能力延期 | 优先完成 P0 双角色闭环和交付文档 | 删除 P1 优化，不扩张范围 |
